# 参考视频还原说明

本文件记录两段成片是怎么对着 `references/BC测试/` 里的原始视频还原的，以及哪些地方是补充的。

## 参考素材

四个 mp4 由 Git LFS 管理，克隆后需要 `git lfs pull` 才会落地真实内容（否则只有 133 字节的指针）。

| 文件 | 规格 | 内容 |
| --- | --- | --- |

| `3D参考下落.mp4` | 1080×1920 / 60fps / 69s | 竖井大网格，方块下落堆叠，整行消除时木屑向两侧爆开 |

## 从参考里提取的关键特征

**拖消**

1. 相邻方块之间没有任何接缝——整片填充区域是一块被雕出来的木板，不是一堆立方体。
   实现见 `render/scenes/dragClear.js` 的 `remapTopFaceUV()`：所有格子共用同一张木纹，
   顶面 UV 按格子在棋盘里的位置重映射，纹理跨格连续；方块尺寸正好等于格宽，
   相邻侧面背靠背互相遮挡，接缝自然消失。
2. 空格是明显下陷的深棕木槽，带格线和内圈暗边。
3. 托盘方块是分离的、带间隙的小立方体，和棋盘上的合并态形成对比。
4. 背景是暖棕竖纹木桌面，中心亮、四角压暗。

**下落**

1. 每块砖顶面有 2×2 颗圆凸点，是最容易认出来的质感。
2. 地形两侧高、中间谷，下半部有一条蛇形裂缝；裂缝让下方每行都缺一格，永远凑不满，
   消除只发生在脚本安排的那几行——这是原视频能长时间保持满屏地形的原因。
3. 消除瞬间木屑从整行向两侧喷出，走抛物线后回落，量非常大。

## 取色

调色不是凭感觉，是从原始帧上直接取样比对的（`render/lib/palette.js` 里的注释标了来源）。
过程中修掉一个真实的色彩管理 bug：`THREE.Color` 内部是线性空间，
程序化木纹把线性值当 sRGB 字节写进 canvas，贴图再被按 sRGB 解码一次，
木头整体偏暗偏橙、蓝通道掉得最狠（砖块 209,140,68 对参考 245,187,131）。
修法见 `render/lib/wood.js` 的 `convertLinearToSRGB()`。修完是 220,174,107 对 230,192,134。

## 两条成片的节奏

时间线是脚本化、确定性的，任意一帧都能独立复现（录制靠 `window.__bc.renderAt(t)`，不依赖墙上时钟）。

| | 拖消 | 下落 |
| --- | --- | --- |
| 时长 | 21.5s | 21.5s |
| 消除节奏 | 单消 → 单消 → 双消 | 单消 ×3 → 四连消 |
| 脚本 | `render/lib/dragTimeline.js` | `render/lib/fallTimeline.js` |

两条时间线的合法性由测试保证（`npm run test:timeline`）：落点不能重叠、必须真的落到底、
必须凑满预期的行、消除节奏必须是设计的那个。改参数改坏了测试会直接报错。

## 与测试题要求的偏差

`references/BC测试/测试规则.md` 原文写的是「参考视频仅用于方向借鉴，请勿被其形式限制；
更希望看到具有突破性和创意的表达」。本次交付按「还原所有细节」执行，
是刻意贴合参考形式的，与上面这条要求方向相反——这一点在交付时已说明。

## 补充的部分

参考视频没提供、按题目要求「自行补充完善」的：背景 UI（分数/Combo 药丸、按钮、
time/score HUD、下一块预览窗）、消除文字（CLEAR / DOUBLE CLEAR / QUAD CLEAR）、
镜头运动（开场推近、四连消前冲）、木屑粒子的具体参数。音效未做。

## 复现

```bash
npm install
git lfs pull                       # 拉参考视频（可选，只影响素材，不影响渲染）
npm run test:timeline              # 校验两条时间线
npm run render                     # 浏览器里实时预览，可拖动查看
npm run record                     # 逐帧渲染并编码出 outputs/*.mp4
```

`npm run record` 需要 Chromium 和完整的 ffmpeg，路径可用 `BC_CHROMIUM` / `BC_FFMPEG` 覆盖。
