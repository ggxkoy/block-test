# 画面色彩客观比对

`scripts/color-check.mjs` — 拿一张目标图当基准，量化另一张图偏了多少。

## 为什么需要这个

「偏灰」是感受，不是结论。同一句「偏灰」，可能是差 5 个色阶，也可能是色相已经彻底没了。
凭肉眼在 viewport 里调灯永远收敛不了，因为 viewport 的曝光和最终渲染本来就不一致。

这个工具做的事很简单：在几个指定区域上取平均色，算三个指标，和基准比。

| 指标 | 含义 | 为什么用它 |
| --- | --- | --- |
| **R−G 差** | 红绿通道差值 | 暖木色在 40 上下，中性灰接近 0。**判断"色相是不是丢了"最灵敏的一个数** |
| 饱和度 | HSV 的 S | 补充判断整体是否发灰 |
| 亮度 | Rec.709 luma | 判断曝光偏差 |
| 纹理方差 | 区域内标准差 | 材质上还有没有纹理；同时用来自检取样框有没有放歪 |

退出码 0 表示全部区域在容差内，1 表示超差——**可以直接当验收卡点接进 CI**。

## 用法

```bash
npm run color-check -- --ref 目标图.png --test 待检图.png

# 换一组取样区域
npm run color-check -- --ref a.png --test b.png --regions scripts/color-regions.ue-r4.json

# 出 JSON，方便接别的流程
npm run color-check -- --ref a.png --test b.png --json
```

从视频里抽帧再比：

```bash
ffmpeg -ss 12 -i 参考.mp4 -frames:v 1 ref.png
ffmpeg -ss 12 -i 我的.mp4  -frames:v 1 test.png
npm run color-check -- --ref ref.png --test test.png
```

依赖 ffmpeg 解码（仓库本来就依赖它），不额外引入图像库。路径用 `BC_FFMPEG` 覆盖。

## 配取样区域

坐标是**相对值** `[x0, y0, x1, y1]`，取值 0–1，所以两张图分辨率不同也能对上同一块内容。
两张图构图不同时用 `ref` / `test` 分别给；构图一致时给一个 `box` 就够。

```json
{
  "tolerance": { "hueGap": 12, "saturation": 0.10, "luma": 26, "maxTexture": 30 },
  "regions": [
    { "name": "浅色木块", "ref": [0.20, 0.24, 0.33, 0.32], "test": [0.25, 0.22, 0.40, 0.28] },
    { "name": "背景木纹", "box": [0.02, 0.65, 0.09, 0.78] }
  ]
}
```

定位坐标的土办法——打个网格上去，每格就是 0.1：

```bash
ffmpeg -i 图.png -vf "scale=400:711,drawgrid=w=40:h=71.1:t=1:c=cyan" 网格图.png
```

**取样框必须落在同一种材质的内部**，不能跨到方块边缘或阴影上，否则平均色是两种材质混出来的，
比出来的数没有意义。工具会用纹理方差自检：超过 `maxTexture` 就报警并跳过色彩判定，
提示你先修坐标。

反过来，有些材质木纹对比本身就强（方差高是真实质感，不是取样错误），
这时候给那个区域单独放宽：

```json
{ "name": "浅色木块", "maxTexture": 70, "ref": [...], "test": [...] }
```

仓库里自带三组：

- `color-regions.default.json` — 参考视频与 three.js 还原版的构图
- `color-regions.ue-r4.json` — 参考视频 vs UE R4 输出
- `color-regions.ue-target.json` — UE 自己的目标风格图 vs UE R4 输出

## 实测：UE R4 偏在哪

拿 UE 自己已确认的目标风格图当基准检 R4 输出：

```
区域              基准 RGB            待检 RGB          ΔR−G    Δ饱和    Δ亮度
浅色木块          (240,191,128)     (155,149,115)      -43    -0.21      -49
空格凹槽          ( 79, 49, 37)     ( 10,  4,  1)      -24    +0.32      -49
背景木纹          (185,106, 52)     (124, 80, 30)      -35    +0.04      -34
```

三个区域全部超差。最要命的是**浅色木块的 R−G 差掉了 43**——目标是 49，R4 只剩 6，
也就是说它已经不是木头色，是中性灰。凹槽更极端，`(10,4,1)` 基本是纯黑，
而目标是 `(79,49,37)` 的暖褐色。

这两个数直接指向修复方向：

1. **先确认木纹贴图真的接到了 Base Color 且按 sRGB 解释**。R−G 差从 49 掉到 6，
   最典型的成因就是贴图没接上（用了灰色默认值），或者被弱天光和 tonemapper 洗掉了。
   这一步不做，调灯只会把灰变成亮一点的灰。
2. **补光严重不足**。凹槽 `(10,4,1)` 说明阴影里完全没有环境光。
   R4 记录的 Skylight 只有 0.42，配 AO 强度 0.72、半径 85，黑成这样是必然的。
   目标是让凹槽落回 `(79,49,37)` 附近。
3. **关掉自动曝光**，锁手动曝光；tonemapper 往 neutral 方向调，别用默认那条会去饱和的曲线。

改完每一轮都跑一次这个工具，看 ΔR−G 有没有往 0 收敛——这是唯一能收敛的办法。

## 局限

- 只看**平均色**，不看构图、造型、动画。它能告诉你「颜色偏了多少」，
  不能告诉你「倒角该不该加」。
- 纹理方差和分辨率有关，两张图尺寸不同时不能直接横比，工具会提示。
- 取样区域要人工配一次并肉眼确认落对了位置。自检只能拦住明显放歪的情况。
