# Three.js 游戏参考效果方案

## 1. 创意方向

核心概念为“最后两格”。首屏直接展示一条只差两格就能消除的横线，让用户在 1 秒内理解目标；随后以拖拽、落地回弹、木屑爆发和 Combo 递进建立爽感。美术延续原素材的暖木质世界，但增加琥珀色轮廓光、景深层次和更克制的界面信息。

建议成片长度 25 秒，竖屏 1080 × 1920，30 fps。

## 2. 25 秒镜头脚本

| 时间 | 画面与操作 | 动效 / 声音 |
| --- | --- | --- |
| 00–02s | 镜头快速推近棋盘；一条横线只缺两格 | 轻微相机冲击，字幕“一步清屏” |
| 02–06s | 两格木块从底部抬起，悬停到目标位 | 目标格琥珀描边，木块高光扫过 |
| 06–09s | 松手，木块从 Z 轴落下并回弹 | 三段落木音，最后一拍加低频 |
| 09–13s | 横线逐格点亮并炸成木屑 | 28ms 错峰消除，粒子向镜头飞出 |
| 13–18s | 第二块补齐横纵两线 | 镜头小幅旋转，`DOUBLE CLEAR` 与 Combo 放大 |
| 18–22s | 大量碎块落下，分数滚动 | 暖橙轮廓光扫过，短促上行音阶 |
| 22–25s | 棋盘回稳，下方三块待选 | “轮到你了”与试玩按钮，保留可操作状态 |

## 3. Three.js 技术拆解

### 场景

- `PerspectiveCamera` 保留轻微透视，镜头正对棋盘但不做完全二维化。
- 木块使用 `BoxGeometry + MeshPhysicalMaterial`，把测试 PNG 作为表面纹理。
- 棋盘由背板、内衬和 8 × 8 格位组成，暗木格与亮木块形成明度对比。
- 半球光负责整体木色，方向光塑造压边阴影，移动点光制造高潮轮廓光。

### 交互

- Pointer Events 同时覆盖鼠标与触屏。
- `Raycaster` 将屏幕坐标投射到棋盘平面，再转换为行列。
- 拖拽过程中实时检测边界和占用状态；可放置时显示暖黄自发光，不可放置时显示红色。
- 落块后检测完整行与列，并用集合去重交叉格。

### 动画

- 落块：Z 轴 3.4 → 0.42，`easeOutBack` 形成干净回弹。
- 消除：逐格延迟 28ms，建立从一端扫到另一端的阅读方向。
- 碎屑：每格 5 个低面数小方块，初速度向外且带旋转，透明/缩放衰减。
- UI：分数、Combo 和爆点文案使用 DOM，保证清晰度并方便广告版本迭代。

### 性能建议

- 成片版建议用 `InstancedMesh` 合并棋盘格和常驻木块。
- 粒子使用对象池，避免高潮段频繁创建和销毁对象。
- 设备像素比上限设为 2；低端机可将阴影和碎屑数量减半。
- 录屏前固定随机种子与动画时间线，避免每次录制节奏不同。

## 4. 从原型到成片

1. 把“自动演示”扩展为完整 25 秒确定性时间线。
2. 增加手指或手势光标，强化用户视角。
3. 加入 2–3 个落木音、消除音和 Combo 上行音阶。
4. 以 1080 × 1920 浏览器画布运行，30 fps 录屏。
5. 剪辑时保留 3%–5% 安全边距，避免平台 UI 遮挡分数和试玩按钮。

## 5. 验收点

- 前 2 秒不依赖说明文字也能理解“补齐即消除”。
- 落点、碰撞、消除三种反馈在颜色、运动和声音上可区分。
- 高潮前后有明显动静对比，碎屑不会遮挡核心棋盘超过 1 秒。
- 15–30 秒内完成一次完整“理解—操作—奖励—邀请再玩”闭环。
